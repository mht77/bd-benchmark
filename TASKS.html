How scoring works

Most tasks are graded deterministically (green — tests, execution, keyed answers, telemetry); open-ended design and analysis are judged (amber — an LLM or a human against a rubric). Tasks that mix methods show each method's weight.

C# test suite  Your code is injected into a console runner and executed with dotnet run.

pytest suite  Your code is injected and run against a hidden pytest suite.

TS type-check + tests  tsc --noEmit type-check plus node --test runtime tests.

SQL result match  The query runs against a seeded SQLite DB; the result set must match the expected one.

scaling  The solution is timed across growing input sizes and scored on its empirical growth exponent.

held-out tests  A held-out suite runs against the agent's final workspace.

final-state grade  The final fixture state and the tool-call trace are graded against the task's domain rules.

solution quality  A held-out benchmark scores the agent's final solution by quality against a tuned reference — a ratio, not a pass count, so there is no ceiling to memorize.

tool discipline  Deterministic process telemetry: tested-before-finishing, valid tool calls, and a graded call-count budget.

LLM judge  One or more judge models score the response against a rubric and reference answer; a panel's verdicts are averaged.

human review  Design quality is scored by hand, per criterion, against written guidance.
